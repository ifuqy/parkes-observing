## 速度与恢复

- 内置浏览器首次可打开登录页，但getTab读取连续超时；重现时改用已登录本地浏览器，不反复重试同一调用。正常可用DOM浏览器优先按控件名定位。
- 360的AX只返回窗口壳，不含网页控件。用截图坐标，反复完整AX不会得到DOM；仍遵守工具刷新要求。
- 同调用中动作后的截图曾落后一个动画帧。截图明显旧时单独刷新一次，不立刻重复点。
- 遮挡时用该窗口AX暴露的Raise动作置前，再截图。多截图区域选对应ID，不猜缩放倍数。
- 浅蓝底和行首勾号不是已选中；深蓝白字才是选中。单击下一行替换上一行。新版逐源单选→Schedule，免Ctrl。
- 所有源追加后一次核对队列足够，不用逐源等实际采集再追加。
- Start后旧Alias可能短时滞留，结合新日志GOTO坐标与队列变化判断，不重复Start。
- 结束前5分钟恢复与定位，前2分钟执行Abort。不要到截止点才处理置前、最大化与查按钮。


## 2026-10-26 新增准备经验

- 两站登录会话可能分别过期；门户成功登录不等于GARIWANG已登录。先打开门户，加载期间可新建第二标签打开控制页；在到场消息截止前完成两站登录，把等待用于准备而非空耗。输入仍按工具规则串行定位焦点，不跨标签盲输凭据。
- 最大化1536×918实测：门户Username约(480,671)、Password约(480,701)、Login约(347,733)；GARIWANG Ident约(217,636)、Password约(217,667)、Login约(122,712)。仅作当前截图定位提示，不重放旧坐标。
- 两站登录后都曾出现“想安全保存此网页的密码吗”提示。右上×约(958,80)关闭；不要点安全保存。弹出层有独立截图区域时用对应截图ID。
- 输入账号并Tab后曾报no monitor found for window，但输入实际已完成。重新取得当前返回的窗口对象、截图观察一次；确认账号和密码焦点后再继续，不重输账号或把密码打进错误位置。恢复仍失败立即报告。
- Current Alerts关闭即可，但不清除故障或绕过保护。常规登录准备不需要反复检查所有设备面板。
- 遇工作人员Starting up同项目且已有所需后续目标，回复Thanks!、检查门户OIC并接管至{OIC_DISPLAY_NAME}，保留既有队列。额外源不是重新加载/调度的理由。
- 截止前将Observing保持前台，当前目标、ID及Abort同屏；OIC证据在准备阶段取得，不到截止点才翻页找。当前Alias精确匹配用户目标是本次停止授权依据；平台审批仍独立生效。
